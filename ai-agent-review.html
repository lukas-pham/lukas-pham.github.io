The problem — and who has it

AI writes code fast, but it is hard to know whether the code does what the ticket asked and whether it follows Shopify's Built for Shopify (BFS) rules. A model that reviews its own work tends to agree with itself.

Who has this problem: me and any small team building Shopify apps with AI, where nobody has time to re-read every line against a 60-item checklist.

Technical decisions

Objectivity comes from the system, not a prompt

Reviewers never see the developer's reasoning. They get the original requirement, the rules, the diff and their own test runs. The handoff file is passed as untrusted data.

The model never decides the verdict

Fail / conditional pass / pass is computed by code from fixed rules. The model only reports items and issues.

No proof, no pass

A pass without verifiable evidence (a file:line that exists, a test run, a screenshot, a measurement) becomes "not enough evidence". Issues without evidence are discarded but still shown.

Rules are data

Each rule set is a versioned JSON file with code, scope, check method and a flag for rules that need real production data. The finance rule set for project 03 swaps the reviewer scopes.

Test tampering is caught without AI

A diff scan flags removed assertions, deleted test files, .skip/.only and trivial asserts.

Trade-offs I accepted

  • Three reviewer calls per round cost more than one — accepted, because one reviewer spanning server, backend and UI misses more.
  • Strict evidence rules make "not enough evidence" common for UI rules until screenshot capture is added. That is honest rather than optimistic.
  • Agent Develop delegates file edits to Claude Code in headless mode instead of re-implementing a coding agent.

What was missed — and what I learned

  • Agent misses: not measured yet. The 30-PR benchmark (20 seeded, 10 clean) is the next step; its real numbers, including misses and false positives, will be published here.
  • During the first end-to-end run, the fake coder kept writing the same skipped test. The loop correctly failed three rounds and escalated — which showed that the fix prompt must include the exact issue list, not just "fix the review".
  • Lesson: a reviewer that cannot attach screenshots will under-report UI problems. Screenshot capture in the sandbox is the first optimisation.
