The problem — and who has it

Large catalogs end up with empty descriptions, missing SEO titles and images without alt text. Writing them by hand takes days; generic AI tools invent materials and sizes that are not true.

Who has this problem: merchants with hundreds of products and no copywriter.

Technical decisions

No write without approval — enforced twice

The write job refuses any draft that is not approved with a reviewer recorded, and the edited draft is re-validated on the server before approval.

"No invented specs" is checked in code

Every number + unit in the output must exist in the product data. Otherwise the draft is blocked until the merchant edits it.

Durable queue in PostgreSQL

Generate / apply / revert are rows in a jobs table, so progress stays correct after reloads or restarts; throttled calls back off longer.

Undo from the live state

Right before writing, the app reads the current content from Shopify and stores it — not the scan-time snapshot.

APIs verified, not remembered

All GraphQL operations were validated against Admin API 2026-10 with the Shopify AI Toolkit; that is how write_files turned out to be required for image alt text.

Trade-offs I accepted

  • The number/unit check is deliberately strict and will sometimes block a correct sentence; the merchant edits it. A false block is cheaper than a false claim on a product page.
  • The worker runs inside the web process in v0. Simple to deploy, but it should move to its own process before real traffic.
  • Translations for multiple markets (nice-to-have) are not built yet.

What was missed — and what I learned

  • Agent misses: not measured yet — this app has not been through Agent Review.
  • The official template's TypeScript config did not include the App Bridge types, so s-app-nav failed type-checking. Found by running the type-check, not by reading the code.
  • I assumed image alt text could be written with the product write scope. The docs say fileUpdate needs write_files. Lesson: check scopes per mutation in the docs every time.
